# Linux Directory Structure

## 1. Introduction

Linux organizes files and directories in a hierarchical structure that begins at the root directory (`/`).

Unlike Windows, where users commonly navigate between drive letters such as `C:` and `D:`, Linux presents its filesystem through a single directory tree. Additional disks and filesystems can be mounted at directories within that tree.

Understanding the directory structure helps DevOps engineers locate configuration files, investigate logs, manage storage, and troubleshoot applications.

## 2. Linux Directory Hierarchy

A simplified Linux filesystem hierarchy looks like this:

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── media
├── mnt
├── opt
├── proc
├── root
├── run
├── sbin
├── sys
├── tmp
├── usr
└── var
```

The exact layout varies by distribution. Some directories may be symbolic links to other locations, and additional directories may exist.

## 3. Important Directories

### `/` — Root Directory

The root directory is the starting point of the Linux filesystem hierarchy.

Every absolute filesystem path begins at `/`.

Example:

```text
/home/ubuntu/scripts/deploy.sh
```

### `/etc` — Configuration Files

`/etc` contains system-wide configuration files.

Examples include:

- `/etc/hosts` — Local hostname-to-address mappings.
- `/etc/os-release` — Linux distribution identification.
- `/etc/fstab` — Configuration for filesystems that may be mounted during startup.
- `/etc/ssh/` — SSH configuration files.

**DevOps use case:** Inspect relevant service configuration when troubleshooting a service or access issue. Validate changes before restarting services.

### `/var` — Variable Data

`/var` contains data that changes during normal system operation.

Examples:

- `/var/log/` — Many system and application logs.
- `/var/cache/` — Cache data.
- `/var/spool/` — Queued work for certain services.

**DevOps use case:** Investigate logs and disk usage when an application fails or a server runs low on space.

### `/home` — User Home Directories

`/home` commonly contains home directories for regular users.

Example:

```text
/home/
├── ubuntu/
├── developer/
└── devops/
```

Users may store scripts, personal files, and user-specific configuration here. Access is controlled by permissions.

**DevOps use case:** Locate user scripts or SSH-related files while troubleshooting a user account.

### `/root` — Root User's Home

`/root` is the home directory of the root administrator account.

It is different from `/`, which is the root of the entire filesystem hierarchy.

### `/usr` — Programs and Shared Resources

`/usr` contains many installed programs, libraries, documentation, and shared resources.

Common subdirectories include:

- `/usr/bin/` — Many user commands.
- `/usr/sbin/` — Many system administration utilities.
- `/usr/lib/` — Libraries and supporting files.
- `/usr/share/` — Shared data and documentation.

**DevOps use case:** Understand where installed commands and software resources may be located.

### `/bin` and `/sbin` — Essential Commands

Traditionally, `/bin` contains essential commands and `/sbin` contains essential system administration utilities.

On many modern distributions, these directories are symbolic links into `/usr`, such as `/usr/bin` and `/usr/sbin`.

### `/lib` and `/lib64` — Libraries

These directories traditionally contain essential shared libraries and, depending on the system, kernel modules.

Their exact layout varies by Linux distribution. Some systems merge these locations into `/usr`.

### `/tmp` — Temporary Files

`/tmp` is used for temporary files created by applications and users.

Files may be removed automatically or during system cleanup. Do not rely on `/tmp` for permanent application data.

### `/opt` — Optional Software

`/opt` is commonly used for additional software packages installed outside standard system locations.

The actual installation path depends on the application and organizational conventions.

### `/dev` — Device Files

`/dev` contains special files representing devices and other interfaces.

Examples:

- `/dev/null` — Discards data written to it.
- `/dev/sda` — A possible disk-device name.
- `/dev/nvme0n1` — A possible NVMe disk-device name.

Device names vary between systems.

### `/proc` — Process and Kernel Information

`/proc` is a virtual filesystem that exposes information about running processes and the kernel.

Examples:

- `/proc/cpuinfo` — CPU information.
- `/proc/meminfo` — Memory information.
- `/proc/<PID>/` — Information associated with a process ID.

Its contents are generally generated by the running kernel rather than stored as ordinary files on disk.

### `/sys` — Kernel and Device Information

`/sys` is a virtual filesystem exposing information about kernel objects, devices, and drivers.

Some entries provide writable interfaces, so do not change them without understanding their purpose and consequences.

### `/boot` — Boot-Related Files

`/boot` commonly contains the Linux kernel, initial RAM filesystem images, and bootloader-related files.

The precise contents depend on the distribution and boot configuration.

### `/run` — Runtime Information

`/run` stores volatile runtime information, such as service state, sockets, and process-related data.

Its contents generally do not persist across reboots.

### `/mnt` and `/media` — Mount Points

- `/mnt` is commonly used for temporary or manual filesystem mounts.
- `/media` is commonly used for removable media.

A mount point is a directory through which a mounted filesystem becomes accessible.

## 4. How to Explore the Directory Structure

### List root-level entries

```bash
ls /
```

### Display detailed directory information

```bash
ls -l /
```

### Identify the current working directory

```bash
pwd
```

### Explore configuration files

```bash
ls /etc
```

### Check filesystem capacity

```bash
df -h
```

### Display mounted filesystems

```bash
findmnt
```

These commands help you understand the structure without modifying system files.

## 5. Practical DevOps Scenarios

### Scenario 1: A service fails to start

Identify the service's configuration location and inspect the relevant configuration. Check the service status and logs before deciding what to change.

### Scenario 2: A server is running out of disk space

Use `df -h` to identify filesystems with limited free space. Investigate the directories consuming space before removing anything.

### Scenario 3: You need to locate an installed command

Commands may be found under `/usr/bin`, `/usr/sbin`, or other locations depending on the distribution and installation method.

You can use:

```bash
command -v <command-name>
```

Replace `<command-name>` with the command you want to locate.

### Scenario 4: You need to identify a mounted disk

Use:

```bash
findmnt
df -h
```

These commands show mounted filesystems and help you understand where their contents are accessible.

## 6. Interview Questions

### Q1. What is the Linux root directory?

The root directory (`/`) is the starting point of the filesystem hierarchy. All absolute paths begin there.

### Q2. What is the difference between `/` and `/root`?

`/` is the root of the entire filesystem hierarchy. `/root` is the home directory of the root administrator account.

### Q3. What is the purpose of `/etc`?

It contains system-wide configuration files.

### Q4. Where are Linux logs stored?

Many logs are located under `/var/log`, although applications may use other locations. Systems using systemd may also provide logs through the journal.

### Q5. What are `/proc` and `/sys`?

They are virtual filesystems exposing information about processes, the kernel, devices, and system state.

### Q6. What is a mount point?

A mount point is a directory through which a mounted filesystem becomes accessible.

### Q7. Why is filesystem knowledge important for DevOps?

It helps with service configuration, log investigation, storage management, application deployments, and troubleshooting.



## 7. Key Takeaway

The Linux directory hierarchy gives files and system resources a predictable organization.

For a DevOps engineer, knowing where to start looking is often the first step toward solving a problem.
